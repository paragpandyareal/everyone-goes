# Deploying the hosted demo (Render + Neon, both free)

The hosted demo runs as a Render free web service (it sleeps when idle, so the first load can take up to a minute) with a free Neon Postgres database.

## 1. Neon (database)
1. Create a free project at neon.tech, in a US region close to Render (Oregon by default).
2. Copy the **pooled** connection string (it contains `-pooler` and ends `?sslmode=require`).

## 2. Render (web service)
1. Render dashboard → New → **Blueprint** → pick this repo. It reads `render.yaml`.
2. Fill the variables marked "sync: false": `DATABASE_URL` (the Neon string), the Trips and Cover Fund client IDs, secrets and emails, `PARENT_EMAILS`, `ANTHROPIC_API_KEY`, `DEMO_LOGINS` (optional, sandbox logins shown to judges) and `APP_BASE_URL` (the `https://<name>.onrender.com` address; add it after the first deploy and redeploy).
3. `LINK_TABLE_KEY`, `APPROVAL_SIGNING_KEY`, `ADMIN_TOKEN` and `STAFF_PASSCODE` are generated by Render. Read `ADMIN_TOKEN` from the service's Environment page for the `/admin` page.

## 3. Webhooks
Register one webhook per app, pointing at the hosted URL, either in developer.paypal.com or with `POST /v1/notifications/webhooks`:
- Trips app → `https://<host>/api/webhooks/paypal/trips`: `INVOICING.INVOICE.PAID`, `INVOICING.INVOICE.UPDATED`, `INVOICING.INVOICE.CANCELLED`.
- Cover Fund app → `https://<host>/api/webhooks/paypal/coverfund`: `PAYMENT.CAPTURE.COMPLETED`, `PAYMENT.CAPTURE.DENIED`, `PAYMENT.PAYOUTSBATCH.SUCCESS`, `VAULT.PAYMENT-TOKEN.CREATED`, `VAULT.PAYMENT-TOKEN.DELETED`.

Put the two webhook IDs in `TRIPS_WEBHOOK_ID` and `COVERFUND_WEBHOOK_ID`. Every webhook is verified with PayPal before it is used.

## 4. Seed the hosted demo
Open `https://<host>/admin`, paste `ADMIN_TOKEN`, and run steps 1 to 5. Pay the 8 parent invoices from the links on that page (as the sandbox parents, by card), and approve the Corner Hardware pledge as the Corner sandbox account when step 2 opens PayPal.
